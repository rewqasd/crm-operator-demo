# CRM × 联通云犀教学演示系统设计规格

日期：2026-09-12  
状态：待用户最终确认后实施

## 1. 目标

把现有单页 CRM 原型重构为一套适合通信运营商政企课程的对标教学工具，清楚展示两类产品的能力边界：

- CRM 负责发现线索、分配线索、联系计划、客户转化、商机推进和销售闭环。
- 联通云犀负责工作手机通信数据采集、外呼规范、身份亮显、通话录音、话后分析、标签洞察、服务质检和数据输出。
- 两者通过“云犀通话结果回写 CRM”形成协同关系，而不是把云犀描述为完整 CRM。

系统继续采用纯静态单页架构、浏览器本地存储和 GitHub Pages 发布，不连接真实电话、云犀平台或企业系统。

## 2. 产品资料依据与口径

设计以金山文档中的以下资料为主要依据：

- 《联通云犀 AI 数悉产品培训——逐字稿与案例整理》
- 《天津河东联通——云犀营销实战课程》
- 《联通云犀云应用标准资费表（全国）》

采用的产品能力包括：

- 云名片：外呼时亮明企业身份，改善陌生号码识别。
- 呼叫控制：配置外呼频率、额度、时段和黑名单。
- 云录音：对符合条件的工作手机通话进行录音沉淀。
- 云转写：把录音转换为可分析文本。
- AI 数悉：生成摘要、客户问题清单、标签、员工评价和分析报告。
- 通话旅程：关联同一客户的多次通话，追踪需求和意向变化。
- 云质检：分析话术规范、服务质量、违规用语和跟进约定。
- 数据看板：展示通话次数、接通率、有效通话、意向分布和人员表现。
- API 输出：模拟把转写文本及标签结果推送至 CRM 或客户业务系统。
- AI 云秘书：忙线或未接场景下提供代接摘要。

口径约束：

- AI 数悉按资料描述为“话后准实时分析”，不能展示为通话中实时产生最终分析结果。
- 演示界面必须区分“产品资料确认能力”和“教学模拟数据”。
- 不承诺所有 CRM 都可直接无缝对接；统一表述为“支持接口，实际接入方式、改造范围和费用需由产品支持确认”。
- 不展示真实账号、密码、电话号码、客户数据、内网地址或受限平台截图。
- 不把云犀描述为规避封号或规避监管的工具。呼叫控制用于合规、授权和有序触达。

## 3. 信息架构

### 3.1 首页与导航顺序

默认首页从“工作台”改为“线索作战台”。左侧导航按教学主线排序：

1. 线索作战台
2. 我的线索
3. 新设企业雷达
4. 线索公海
5. 查重与分配
6. 联系客户
7. 跟进任务
8. 客户与商机
9. 成交管理
10. 经营分析
11. 云犀功能演示

“云犀功能演示”放在底部独立分组，以不同背景、分隔线和产品标签与 CRM 主体区分。

### 3.2 模块合并与精简

- “联系人”并入客户 360°画像，不再单独占据一级导航。
- “电话工作台、通话记录、录音转写、通话质检”合并为“联系客户”，使用页内标签切换。
- “任务日历、外勤拜访”合并为“跟进任务”。
- “客户管理、商机看板”合并为“客户与商机”，保留画像与阶段看板。
- “合同、订单、回款、产品报价”合并为“成交管理”，降低授课主线中的视觉优先级。
- 删除没有真实交互、只显示占位提示且不支持教学目标的按钮和冗余卡片。

底层状态结构继续保留客户、联系人、商机、合同、订单、回款等数据，以保证闭环和原有教学功能不丢失。

## 4. CRM 线索主流程

### 4.1 线索作战台

首页突出以下内容：

- 今日待联系、今日新增、超时未跟进、高意向线索、线索转化率。
- 地市、区县、行业、成立时间、评分、状态、产品机会筛选。
- “今日优先联系”队列，解释排序理由。
- 线索漏斗：待领取、已领取、已联系、有效线索、已转客户。
- 线索来源与数据说明。

### 4.2 线索行内操作

每条线索提供同一套操作：

- 查看画像
- 领取/分配
- 模拟拨打
- 记录联系结果
- 创建跟进任务
- 转为客户及商机
- 放入公海/回收

从线索页发起拨打时，联系客户工作台直接载入该企业，无需先进入联系人页面。

### 4.3 联系结果回写

挂断电话后统一写入：

- 通话方向、时间、时长和接通状态
- 联系结果和客户意向
- 通话摘要、关键词和产品机会
- 质检结果
- 下一次跟进任务
- 线索状态和评分变化

刷新页面后，关联数据仍从 localStorage 恢复；重复演示通过稳定 ID 更新记录，不生成重复客户和任务。

## 5. 云犀功能演示区

### 5.1 演示首页

云犀区采用教学仿真界面，不复制受限平台 UI。首页由九张可点击能力卡组成：

1. 云名片
2. 呼叫控制
3. 云录音
4. AI 数悉
5. 标签洞察
6. 通话旅程
7. 云质检
8. 数据看板
9. API 回写 CRM

另提供“AI 云秘书”未接来电场景入口。

每张卡必须说明：客户问题、产品动作、演示结果、适用边界。

### 5.2 可操作演示

#### 云名片

- 选择企业身份和外呼员工。
- 在模拟客户手机上显示企业名称、服务类型和号码标记状态。
- 对比“陌生号码”和“企业身份亮显”的接听体验。
- 标注终端显示效果以实际终端和配置为准。

#### 呼叫控制

- 设置日外呼额度、单客户联系次数、允许时段和黑名单。
- 选择一个违反规则的拨打行为，系统阻止并解释命中规则。
- 强调授权、合规、时段管理和避免重复触达。

#### 云录音与话后分析

- 模拟正常工作手机拨号，不把云犀画成软电话拨号器。
- 通话中只显示录音采集状态和通话计时。
- 挂断后进入“录音已上传—转写处理中—AI 分析处理中—分析完成”状态链。
- 教学演示可以压缩等待时间，但界面明确标注“实际为话后准实时处理”。

#### AI 数悉与标签洞察

- 展示全文转写、通话摘要、客户问题清单、待办建议。
- 展示意向等级、预算区间、需求产品、情绪、违规用语和服务评分等标签。
- 支持切换标签模板，说明标签可按企业场景配置。

#### 通话旅程

- 以同一客户的首次联系、T+2 跟进和方案确认三次通话构建时间线。
- 展示意向、预算、核心问题和下一步动作的变化。

#### 云质检与数据看板

- 质检维度包括身份说明、需求挖掘、合规表达、信息确认、下一步约定。
- 看板包括拨打量、接通率、有效通话率、高意向数量、风险通话和团队排行。
- 指标全部标注为教学模拟。

#### API 回写

- 显示“选择字段—发送—CRM 接收—线索更新”的动画。
- 回写摘要、意向、标签、质检分、下次跟进时间。
- 数据进入 CRM 后可立即在线索作战台和客户画像中查看。

## 6. 自动演示

顶部自动演示入口改成模式选择器：

### 6.1 CRM 线索转化演示

新设企业雷达发现线索 → 领取分配 → 联系客户 → 记录结果 → T+2 跟进 → 转客户/商机 → 报价及结单。

### 6.2 云犀通话能力演示

选择员工号码 → 配置呼叫控制 → 云名片亮显 → 正常工作手机拨号 → 云录音 → 挂断 → 话后转写 → AI 标签 → 云质检 → 数据看板。

### 6.3 CRM × 云犀协同演示

CRM 选择高优先级线索 → 云犀完成通信数据采集及话后分析 → 通过 API 模拟回写 → CRM 更新线索评分、客户画像及 T+2 任务。

三种演示均保留播放、暂停、上一步、下一步、倍速、重播和退出控制。演示前保存快照，退出时允许保留结果或恢复数据。

## 7. 状态、错误和隐私处理

- 全部操作在浏览器内完成，不调用电话、短信、云犀、联通或第三方 API。
- 所有电话号码使用脱敏格式，所有人物及通话内容标记为模拟。
- 云犀分析任务具有 processing、completed 和 failed 状态；失败时允许重新分析，不丢失录音记录。
- 呼叫规则命中时显示具体原因，不模拟真实封号、号码申诉或监管结论。
- API 回写失败时保留待同步记录，允许再次点击同步。
- 全局提供“一键重置教学数据”。

## 8. aTrust 使用与隔离建议

推荐建立专用访问环境，不在主力 Mac 上长期改变 DNS 或代理：

1. 首选：VMware Fusion 中建立 Windows 虚拟机，使用 NAT 网络，只在虚拟机内安装 aTrust。
2. 完成 aTrust、浏览器和必要证书配置后保存干净快照；授课前启动，结束后关机或恢复快照。
3. 若改用闲置电脑，优先使用经联通侧确认兼容的 Windows 环境；Linux 必须先确认具体 aTrust 服务端版本、客户端版本和 Ubuntu/UOS/麒麟支持范围。
4. 需要更轻量访问时，向联通平台管理员申请应用级发布、浏览器资源或分流策略，由管理端配置，不在客户端绕过安全策略。
5. 不把 aTrust 凭据、云犀数据或内网地址放入公开 GitHub 仓库。

该网络隔离方案属于部署建议，不在本静态演示系统中自动修改 DNS、代理、虚拟机或 aTrust 设置。

## 9. 实施边界

本轮包括：

- 重排导航和默认首页。
- 合并并精简现有 CRM 页面。
- 强化线索与联系客户闭环。
- 新增独立云犀教学仿真区及可操作能力演示。
- 新增三种自动演示路线。
- 修正 AI 数悉实时性等产品口径。
- 更新 README 和数据说明。
- 浏览器测试并发布到现有 GitHub Pages。

本轮不包括：

- 真实接入云犀、CRM、电话、短信、联通 API 或 aTrust。
- 复制真实云犀内网页面、账号体系或受限数据。
- 自动配置虚拟机、DNS、系统代理或零信任策略。
- 验证具体客户合同、资费和地区办理政策。

## 10. 验收标准

- 打开系统后第一屏明确突出线索，不再以普通经营报表为中心。
- 用户能从任意线索直接进入联系客户流程，并在挂断后看到状态和任务回写。
- CRM 一级导航数量减少，原有关键交易数据仍可访问。
- 云犀演示区与 CRM 视觉上明确分区，九项能力均可点击演示。
- 云名片、呼叫控制、云录音、话后转写、AI 标签、通话旅程、质检、看板和 API 回写形成完整演示链。
- 页面不把 AI 数悉描述为实时最终分析，不宣传规避封号，不承诺无条件对接任何 CRM。
- 三种自动演示均可完整播放、暂停、跳步、退出和重置。
- 重复演示不会生成重复客户、通话任务、合同或回款。
- 1366px、1024px 和 720px 宽度无页面级横向溢出，弹窗和演示控制可用。
- JavaScript 无运行时错误，GitHub Pages 线上版本返回 HTTP 200。
- 发布内容不包含真实联系方式、账号、密码、内网地址或个人隐私。
